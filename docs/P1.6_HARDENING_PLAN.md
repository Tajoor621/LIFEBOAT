# P1.6 — Vault hardening plan

Status: planned; do not expose the service publicly or use it as the only copy of irreplaceable data.

P1.6 follows the green automated P1.5 baseline. Its purpose is to close the highest-risk gaps in the vault boundary before starting the Android agent.

## Work order

1. **Reproducible dependencies**
   - Generate and commit the workspace `Cargo.lock`.
   - Change CI and Docker builds to use `--locked`.
   - Review dependency updates deliberately; do not silently resolve new versions in release builds.

2. **Request resource boundaries**
   - Enforce route-specific body limits before extracting/allocating request bodies.
   - Keep the manifest limit at or below 8 MiB and encrypted object/chunk limits aligned with the upload protocol.
   - Reject oversized Content-Length and streamed bodies consistently; test missing, false, and chunked Content-Length cases.
   - Ensure rejected requests do not create sessions, files, or quota reservations.

3. **Credential lifecycle**
   - Add a versioned credential file format and a safe offline enrollment/rotation command.
   - Support two valid token generations during a bounded rotation window, then revoke the old token.
   - Never expose raw tokens in logs, health responses, errors, or audit events.
   - Keep online enrollment out of scope until device identity and owner authorization are specified.

4. **Durable audit and storage safety**
   - Add an append-only, integrity-linked event ledger for security-relevant state transitions.
   - Record actor/device ID, action, object/session ID, result, and timestamp; never record secrets or plaintext content.
   - Define retention and deletion semantics without weakening immutable object guarantees.
   - Test restart, disk-full, permission denial, partial rename, and interrupted fsync behavior.

5. **Operational boundary**
   - Add explicit configuration validation and fail closed on unsafe public bind/TLS settings.
   - Document supported single-process deployment and backup/restore of the vault volume.
   - Add deployment smoke tests and a clean-environment restore rehearsal.

## Required automated gates

- `cargo fmt --all -- --check`
- `cargo test --workspace --all-targets`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo build --locked --workspace --release`
- `docker build --tag lifeboat-vault:ci .`

Add focused tests for every request-size boundary, token rotation/revocation, audit-chain tampering, process restart, and filesystem failure. Do not weaken or skip existing tests to make the pipeline green.

## Explicit non-goals

- No Android data collection or background agent in P1.6.
- No multi-node deployment until shared rate limiting, locking, and audit consistency are designed.
- No public Internet deployment without TLS, firewalling, credential lifecycle, monitoring, and independent security review.
- No wipe command or remote destructive action in this phase.

## Exit criteria

P1.6 exits only when the lockfile is committed and enforced, body limits are applied before body extraction, credential rotation/revocation is tested, audit integrity is verified across restart, storage failure tests pass, and the documented deployment/recovery rehearsal is recorded.
