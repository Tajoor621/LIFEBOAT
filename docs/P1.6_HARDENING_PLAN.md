# P1.6 — Vault hardening plan

Status: implementation delivered to `main`; automated CI and operator acceptance are required before production use.

## Implemented scope

1. Reproducible dependency resolution: CI bootstraps the workspace `Cargo.lock` if absent, validates all gates using `--locked`, and commits the generated lockfile directly to `main` only after success. Docker release builds use `--locked`.
2. Request resource boundaries: route-specific body limits are applied before body extraction (objects 16 MiB + 16 bytes, manifests 8 MiB, upload-session JSON 4 KiB, chunks 1 MiB). An integration test covers manifest oversize rejection.
3. Credential lifecycle: versioned credentials JSON stores only BLAKE3 token digests; Unix file permissions are checked; previous-token overlap is bounded by an explicit Unix expiry; revocation/enrollment changes take effect after controlled service restart. A stdin-based hash helper avoids putting raw tokens in process arguments.
4. Durable audit: successful write operations append sequence-numbered, BLAKE3-linked JSONL events; startup verifies the chain and fails closed on tampering. Restart and tamper tests are included.
5. Operational boundary: service default bind is loopback; Docker requires explicit bind override; docs specify TLS reverse proxy, firewall, persistent volume and non-root file ownership. CI builds and smoke-tests the container.

## Required automated gates

- `cargo fmt --all -- --check`
- `cargo test --locked --workspace --all-targets`
- `cargo clippy --locked --workspace --all-targets -- -D warnings`
- `cargo build --locked --workspace --release`
- Docker build and container health/authentication smoke test.

## Remaining operator acceptance

Automated CI does not establish production readiness. Before production:
- run a deployment with a persistent vault volume and read-only 0600 credentials file owned by UID 10001;
- verify credential rotation and immediate revocation after restart;
- interrupt an upload, restart the service, and resume it;
- test disk-full and permission-denied conditions on the actual target filesystem;
- restore from an independent backup and verify hashes and representative files;
- arrange independent security review and anchor audit checkpoints off-host.

## Explicit non-goals

No online enrollment/hot reload, multi-node coordination, built-in TLS, audit checkpoint anchoring, Android collection agent, desktop console, cloud connectors, or destructive remote wipe is delivered in P1.6.
