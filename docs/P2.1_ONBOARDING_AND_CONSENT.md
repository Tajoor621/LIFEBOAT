# P2.1 — Onboarding and explicit consent

## Delivered

- Visible onboarding explains the four initial data categories and intended scope.
- Contacts, photos, videos, and documents are separate opt-in choices; none is preselected on a fresh install.
- The owner must check an explicit confirmation and select at least one category before preferences can be saved.
- Preferences are stored locally in app-private SharedPreferences.
- The owner can withdraw consent and clear all saved choices.
- Permission observations distinguish not requested, granted, denied, permanently denied, limited, revoked, not applicable, and unknown.
- Unknown and revoked are never treated as access. Limited access is not full access.

## Explicit non-capabilities

P2.1 does not request Android permissions, query Contacts or MediaStore, copy files, create a snapshot, encrypt data, access the network, or upload anything. Saving consent preferences is not a backup operation. A later collection action must explain its exact scope and ask for a separate just-in-time confirmation.

## Acceptance

- Fresh install has all choices off and confirmation unchecked.
- Save is rejected unless confirmation is checked and at least one class is selected.
- Saved choices survive app restart.
- Withdraw clears confirmation and every selected class.
- Unknown, denied, revoked, and not-requested states never count as access.
- Limited access is partial scope, not full access.
