# P2.3 — Owner-selected media inventory

## Scope
- Photos and videos remain separate consent categories and collection starts only after saved explicit consent and a separate owner action.
- Android 8–12 uses legacy external-storage read permission, bounded to API 32.
- Android 13 uses separate image and video permissions.
- Android 14+ requests granular image/video permissions and selected-visual-media permission. Selected-only grants are reported PARTIAL, never FULL.
- MediaStore queries metadata only: item count and measured byte totals. The implementation does not open media streams, copy media, persist names/paths/URIs, create backup files, encrypt, or upload.
- Cancellation is checked during provider iteration. Documents remain deferred to Storage Access Framework.

## Evidence and limitations
The inventory describes only provider-visible items under the current permission scope. Selected-only access is partial. Counts do not prove cloud placeholders, removable media, inaccessible volumes, or every OEM-specific item are included. A zero result is not proof of an empty device unless the query completed successfully and scope is understood.

This is metadata inventory only, not media backup. P2.4 must add reviewed on-device encryption and manifest generation before upload.

## Required device acceptance
Test Android 8–12 legacy permissions; Android 13 image-only/video-only/both; Android 14+ full and selected-only access; denial and revocation; large and empty libraries; removable storage; cloud placeholders; HEIC and video; cancellation; no sensitive names/paths/URIs in logs or persistent evidence; Samsung One UI and Pixel/AOSP.
